# 시작하기 (프론트엔드 개발 환경 세팅)

처음 세팅하는 팀원이 위에서부터 순서대로 따라 하면 된다.

---

## 1. 처음 한 번만

### 1-1. 설치
- **Git**: https://git-scm.com
- **Node.js (LTS, v20 이상 권장)**: https://nodejs.org

### 1-2. 코드 받기 및 패키지 설치
```bash
git clone <저장소_주소>
cd GDGoC_project_frontend_repository
npm install
```

### 1-3. 환경변수 설정 (선택)
기본값으로 동작하지만, 로컬 설정을 바꾸려면 `.env.example`을 복사해 `.env`를 만든다.
```bash
cp .env.example .env
```

| 변수 | 기본값 | 설명 |
|---|---|---|
| `VITE_API_BASE_URL` | `/api/v1` | 백엔드 API 기본 경로 (로컬은 Vite 프록시, 배포는 Firebase Hosting rewrite 사용) |
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:8000` | 로컬 개발 시 Vite가 `/api`, `/static` 요청을 넘길 백엔드 서버 주소 |

로컬에서는 백엔드 서버를 별도로 실행하거나 `.env`의 `VITE_API_PROXY_TARGET`을 원격 서버 주소로 지정한 뒤 `http://localhost:5173`으로 접속한다. Vite 개발 서버가 `/api` 요청을 프록시하므로 별도 CORS 설정 없이 호출된다.

### 1-4. 개발 서버 실행
```bash
npm run dev
```

---

## 2. 주요 명령어

| 작업 | 명령어 | 설명 |
|---|---|---|
| 패키지 설치 | `npm install` | `package.json` 기준 의존성 설치 |
| 개발 서버 실행 | `npm run dev` | Vite 개발 서버 실행 (`http://localhost:5173`) |
| 빌드 및 타입 검사 | `npm run build` | `tsc -b` 타입 검사 후 프로덕션 번들 생성 |
| 빌드 결과 미리보기 | `npm run preview` | `dist/` 빌드 결과물 로컬 실행 |

---

## 3. 배포 (Firebase Hosting)

- `firebase.json`에서 `/api/**` 요청은 Cloud Run 백엔드 서비스로 연결(rewrite)되고, 나머지 경로는 SPA(`/index.html`)로 라우팅된다.
- GitHub Actions(`.github/workflows/ci.yml`, `firebase-hosting.yml`)가 PR마다 빌드 검증 및 Preview 채널 배포, `main` 머지 시 live 배포를 수행한다(배포 워크플로는 저장소 Secret `FIREBASE_SERVICE_ACCOUNT_GDG_1234` 등록 후 활성화).
- 로컬에서 수동 Preview 배포가 필요할 때:
```bash
npm run build
firebase hosting:channel:deploy preview --expires 7d
```
